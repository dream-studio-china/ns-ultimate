# 新增门店配置操作手册

本文用于在 NS Ultimate 管理后台开通一家新门店。建议严格按照下面的顺序操作，每一步完成并核对后再进入下一步。

## 开始前

确认当前操作账号可以登录管理后台，并具备管理员权限。门店、商品、打印机、汇付和微信配置涉及不同业务模块；如果菜单或角色不存在，先由部署管理员确认对应授权数据已经初始化。

只给账号分配完成工作所需的最小权限。门店成员角色和权限角色是两个不同的概念：

- **门店成员**决定账号是否可以进入并操作该门店。
- **权限角色分配**决定账号进入门店后能执行哪些操作。

完成后建议记录以下信息，后续配置会用到：

- 门店名称
- 门店编码
- 门店 UUID
- 成员账号和用户 UUID
- 会员角色及已分配的业务角色
- 打印机设备 UUID、模板 UUID
- 汇付商户和门店支付方式
- 微信应用、商户号及门店绑定关系

## 1. 创建门店

菜单：**门店管理 → 门店 → 新增**

填写门店基础信息：

1. **编码**：门店的唯一业务编码，保存后要避免随意变更。
2. **名称**：对外展示和后台识别的门店名称。
3. **状态**：新门店先选择“营业中”。准备阶段需要暂停时选择“停用”，闭店选择“关闭”。
4. **时区**：一般填写 `Asia/Shanghai`。报表日期、营业日以及部分支付时间都会使用该时区。
5. **联系方式**：按实际需要填写联系人、电话等信息。
6. **地址**：按实际经营地址填写。
7. **门店设置**：根据业务需要配置接单、库存和履约核销要求。
8. **支付设置**：除非该门店确实使用旧版通用支付配置，否则不要在这里填写汇付配置。汇付应在第 7 步的“门店汇付设置”中配置。

保存后进入门店详情，记录门店的 **UUID**。后续权限范围、打印机、汇付和微信配置都需要准确选择或绑定这家门店。

完成标准：

- 门店状态为“营业中”。
- 时区正确。
- 可以取得门店 UUID。
- 门店列表中只出现一家目标门店，没有重复编码。

## 2. 增加门店成员账号

这一步分为“创建系统账号”和“加入门店”两个动作。

### 2.1 创建或确认系统账号

菜单：**用户管理 → 用户**

- 如果账号已经存在，搜索用户名并记录用户 UUID。
- 如果账号不存在，点击新增，填写用户名、邮箱、手机号，并设置初始密码。
- 普通门店员工只保留 `ROLE_USER`，不要分配 `ROLE_ADMIN` 或 `ROLE_SUPER_ADMIN`。
- 把初始密码通过安全方式交给员工，并要求首次登录后修改。

### 2.2 将账号加入门店

菜单：**门店管理 → 成员管理**

1. 选择目标门店。
2. 点击“新增或更新成员”。
3. 选择上一步创建或确认的用户账号。
4. 选择会员角色：
   - **所有者**：门店负责人，用于保留最终管理责任人。
   - **经理**：日常经营管理。
   - **店员**：门店日常操作。
   - **履约人员**：接单、履约等订单处理。
5. 保存并确认成员状态为“有效”。

注意事项：

- 会员角色只表示成员在门店中的身份，不等于已经获得所有业务操作权限。
- 即使账号已有会员关系，没有第 3 步的业务角色分配时，仍然不能执行对应业务操作。
- 每家门店均必须保留至少一名有效所有者；系统会阻止停用或撤销最后一名所有者。

完成标准：

- 目标账号在目标门店的成员列表中存在。
- 成员状态为“有效”。
- 账号登录收银端后可以选择该门店，并读取自己的成员身份。

## 3. 为成员账号增加权限授权

菜单：**权限管理 → 角色分配**

角色分配必须使用“门店”范围，不能把门店业务角色分配到全局范围。

操作步骤：

1. 点击新增角色分配。
2. **用户**：搜索并选择第 2 步的账号。
3. **角色**：选择所需的门店范围业务角色。
4. **范围类型**：选择“门店”。
5. **范围 UUID / 门店**：选择目标门店。
6. 保存。
7. 如果账号需要多个能力，按角色逐条新增分配。

常见角色示例：

| 工作职责 | 可优先考虑的角色 |
| --- | --- |
| 商品维护 | 门店商品目录管理员、门店商品目录操作员 |
| 售罄和恢复可售 | 门店可售状态操作员 |
| 查看订单 | 门店订单查看员 |
| 接单、履约、核销 | 门店订单操作员 |
| 订单退款 | 门店订单退款操作员 |
| 订单打印 | 门店订单打印操作员 |
| 桌台和场次管理 | 门店桌台管理员、桌台会话操作员 |
| 桌台订单编辑、取消或合并 | 桌台订单编辑员、桌台订单取消员、桌台订单合并员 |
| 门店汇付设置 | 门店汇付管理员 |
| 门店微信设置 | 门店微信管理员 |

建议按岗位组合角色，不要为了省事直接分配全部权限。退款、关闭支付和商品删除属于高风险能力，应单独确认责任人。

完成标准：

- “角色分配”中存在用户、业务角色、目标门店三者完全匹配的记录。
- 范围类型全部为“门店”，范围 UUID 不是空值。
- 账号重新登录或重新连接门店后，可以看到对应菜单和操作按钮。
- 未授权的操作不会显示，或由后端返回 403。

## 4. 设置门店商品

菜单：**商品管理**

### 4.1 创建商品分类

进入 **商品分类**，创建门店需要的分类，例如“咖啡”“茶饮”“甜点”。新门店可以手工创建，也可以使用列表上方的“从门店复制”功能。

复制时：

- 源门店选择已有配置的门店。
- 目标门店选择本次新门店。
- 核对分类名称、层级、`slug` 和启用状态。
- 目标门店相同 `slug` 的分类会复用，不会重复创建。

### 4.2 创建门店商品

进入 **商品 → 新增**，至少完成以下字段：

1. **商品名称**。
2. **商品描述**。
3. **商品分类**。
4. **门店**：必须选择本次新增的门店。不要留空，否则可能成为全局商品。
5. **排序**：控制商品展示顺序。
6. **推荐等级**：按需要设置。
7. **售罄状态**：新品默认应为“未售罄”。
8. **状态**：选择“启用”。
9. **封面和副标题**：按需要配置。
10. **商品设置**：按需要设置厨房打印、售票窗口等选项。
11. **规格**：商品有大小杯、冷热、加料等差异时，保存商品后进入规格页新增规格、价格、状态和排序。

也可以使用 **商品 → 从门店复制**，把源门店商品复制到新门店。复制后必须逐项核对：

- 商品是否绑定到正确门店。
- 分类是否映射到目标门店分类。
- 规格和价格是否正确。
- 商品状态和售罄状态是否符合新门店。
- 厨房打印和销售时段设置是否正确。

完成标准：

- 商品列表按新门店筛选后可以看到完整商品。
- 商品状态为启用，未售罄。
- 每个需要售卖的商品至少有一个有效规格和价格。
- 分类、规格、图片和商品设置均正确。

## 5. 增加打印设备

打印至少需要“打印账号”和“打印设备”。打印模板也必须在第 6 步之前准备好。

### 5.1 创建打印账号

菜单：**打印管理 → 打印账号**

填写：

- 打印服务商：目前生产可用的是芯烨云 `xpyun`。
- 账号名称。
- 开发者 ID。
- 开发者密钥。

开发者密钥会加密保存，创建后不会回显。必须先由部署环境配置好打印机密钥加密参数；否则不要创建生产账号。

### 5.2 新增打印设备

菜单：**打印管理 → 打印设备 → 新增**

填写：

1. **打印账号**：选择上一步创建的账号。
2. **设备名称**：便于门店识别的名称。
3. **设备序列号**：必须与打印机实际序列号一致。
4. **打印机类型**：小票机选择“小票”，标签机选择“标签”。
5. **门店**：选择本次新增门店。
6. **型号**：按需要填写。
7. **标签宽高**：标签机需要填写，小票机按需要处理。
8. **启用**：设置为启用。

保存时，系统会向打印服务商注册设备。注册失败时不要反复创建重复记录，先检查账号、序列号和网络状态。

### 5.3 创建打印模板

菜单：**打印管理 → 打印模板**

创建与设备类型一致的模板：

- 小票设备只能使用小票模板。
- 标签设备只能使用标签模板。
- 选择“整单一张”或“商品按数量逐张”。
- 按需要配置商品过滤条件和模板 JSON。
- 保存后使用模板预览确认排版和字段。

完成标准：

- 打印账号启用。
- 设备绑定正确门店并启用。
- 设备状态查询正常。
- 存在与设备类型匹配的模板。
- 模板预览可以正常渲染。

## 6. 增加打印规则

菜单：**打印管理 → 订单打印规则 → 新增**

填写：

1. **门店**：选择目标门店。
2. **名称**：例如“新订单厨房小票”“付款后结账小票”。
3. **启用**：确认所有字段后打开。新规则建议先保存为停用，验证后再启用。
4. **打印时机**：可以选择订单确认后、付款成功后、门店接单后、手动打印。
5. **条件匹配**：选择“全部条件满足”或“任一条件满足”。
6. **条件**：按订单状态或订单 metadata 配置；不需要条件时保持为空。
7. **打印设备**：只能选择属于本门店的设备。
8. **打印模板**：只能选择与设备类型一致的模板。
9. **份数**：按门店需要设置。

规则只负责在匹配事件发生时生成打印请求，不会直接完成物理打印。服务器必须持续运行打印派发任务：

```sh
php integration/backend/bin/console app:printer:dispatch-orders
```

应按部署规范配置为定时任务或常驻 worker。没有运行该任务时，订单可能已经匹配规则，但打印机不会收到任务。

完成标准：

- 规则绑定正确门店、设备和模板。
- 规则处于启用状态。
- 打印时机和条件符合业务要求。
- 打印派发任务已运行。
- 创建测试订单后，可以在打印任务中看到请求和最终状态。

## 7. 设置门店汇付支付

汇付支付需要同时满足：汇付接入配置启用、汇付商户启用、商户具备对应支付能力、商户已授权给门店、门店汇付设置启用。任何一项缺失都可能导致门店可用支付方式为空。

### 7.1 确认全局汇付配置

菜单：**汇付配置**

由平台管理员确认以下对象已经存在且启用：

- **汇付接入配置**：环境、系统 ID、产品 ID、商户私钥、汇付公钥和异步通知公钥。
- **汇付商户**：汇付商户号、所属接入配置、支付能力和启用状态。

支付能力示例为 `jspay`、`native`、`quickpay`。商户能力必须与门店准备启用的方式一致。

### 7.2 增加汇付商户门店授权

菜单：**汇付配置 → 汇付商户门店授权 → 新增**

填写：

- **汇付商户**：选择平台已配置且启用的商户。
- **门店**：选择本次新增门店。

保存后确认授权记录存在。未建立该授权时，门店不能使用对应汇付商户发起支付。

### 7.3 配置门店汇付设置

菜单：**汇付配置 → 门店汇付设置 → 新增**

填写：

1. **门店**：选择目标门店。
2. **汇付商户**：选择上一步已授权的商户。
3. **启用**：打开。
4. **允许的支付方式**：填写与商户能力一致的 JSON 数组，例如 `["native", "jspay"]`。
5. **默认支付方式**：必须包含在允许方式中。
6. **启用 POS**：只有在门店实际使用汇付 POS 并已配置设备时启用。

支付方式说明：

- `jspay`：微信 JSAPI。用户必须先通过该门店配置的微信应用登录，服务端需要取得对应 OpenID。
- `native`：扫码支付二维码。
- `quickpay`：已有适配代码，但真实产品契约需要按实际签约产品完成验证；未验证前不要直接用于生产。

完成标准：

- 汇付接入配置启用且凭据可用。
- 汇付商户启用，并且能力包含门店选择的支付方式。
- 商户门店授权存在。
- 门店汇付设置启用，默认方式在允许列表中。
- 公开支付摘要返回正确的 `channels` 和 `defaultChannel`。
- 使用测试订单可以创建支付尝试，并且不是仅界面显示可用。

## 8. 增加门店微信配置

微信登录和微信 JSAPI 支付依赖门店级微信应用绑定。

### 8.1 创建微信应用

菜单：**微信配置 → 微信应用配置 → 新增**

按实际应用类型分别创建：

- **小程序**：名称、类型、AppID、AppSecret。
- **公众号**：名称、类型、AppID、AppSecret；使用消息或网页授权时再填写服务器 Token 和 EncodingAESKey。

同一门店可以同时绑定小程序和公众号，但每种类型只能选择一个正确应用。

### 8.2 创建微信商户（微信支付需要）

如果门店使用微信支付，进入 **微信配置 → 微信商户配置**，配置：

- 商户名称。
- 商户号。
- 直连商户或服务商模式。
- API v3 密钥。
- 商户私钥和商户 API 证书。
- 微信支付平台证书。
- 服务商模式还需要服务商 AppID 和子商户号。

使用汇付微信 JSAPI 时，汇付模块使用门店绑定微信应用的 AppID 和 OpenID；使用微信支付时，还需要正确绑定微信商户。

### 8.3 绑定门店微信设置

菜单：**微信配置 → 门店微信设置 → 新增**

填写：

1. **门店**：选择目标门店。
2. **门店小程序应用**：选择类型为小程序的应用，可按需要使用。
3. **门店公众号应用**：选择类型为公众号的应用，可按需要使用。
4. **门店微信商户**：使用微信支付时选择。

至少需要绑定一个小程序或公众号应用。保存后，前端登录必须携带正确的 `store_uuid`，服务端会按门店解析对应 AppID 和凭据。

完成标准：

- 微信应用 AppID 和 AppSecret 正确。
- 门店微信设置绑定了正确应用。
- 微信支付场景绑定了正确商户和证书。
- 用户在目标门店完成微信登录。
- 服务端生成的 OpenID 属于该门店配置的 AppID。
- 微信 JSAPI 支付或扫码链路可以完成测试支付和回调确认。

## 最终验收清单

- [ ] 门店编码唯一，状态和时区正确。
- [ ] 操作账号已加入门店且成员状态为有效。
- [ ] 账号只获得岗位需要的门店范围角色。
- [ ] 商品、分类、规格、价格和图片正确。
- [ ] 打印账号、设备、模板和规则全部配置完成。
- [ ] 打印派发任务正在运行。
- [ ] 汇付商户能力、门店授权和门店设置一致。
- [ ] 汇付支付渠道列表和默认渠道符合预期。
- [ ] 门店微信应用和商户绑定正确。
- [ ] 使用普通员工账号完成登录、商品读取、订单处理、打印和支付测试。
- [ ] 使用未授权账号确认无法执行退款、关闭支付、修改商品等敏感操作。

## 常见问题

### 账号能看到门店，但没有操作按钮

检查第 3 步。门店成员关系只允许账号进入门店，实际操作还需要门店范围的角色分配。重新登录或重新连接门店刷新权限快照。

### 商品保存后不属于目标门店

检查商品的“门店”字段。新门店商品不要留空；复制商品后也要按目标门店筛选核对。

### 打印规则已启用，但打印机没有出纸

依次检查设备是否启用、设备和模板类型是否一致、规则是否启用、订单事件和条件是否匹配、打印派发任务是否运行。

### 门店支付界面没有可用支付方式

依次检查汇付接入配置、商户启用状态、商户支付能力、商户门店授权、门店汇付设置、允许方式和默认方式。

### 微信登录或 JSAPI 支付失败

检查门店微信应用是否绑定正确、AppID 与登录时提交的 `store_uuid` 是否一致、AppSecret 是否有效、用户是否通过该 AppID 登录并取得 OpenID。
