# Contracts

Document stable, cross-layer interfaces here: ownership, names, input/output, registration mechanism, compatibility expectations, and tests. Keep business-specific rules in `business/` and core implementation details in the relevant core repository.

The initial contracts are described in [`admin-composition.md`](admin-composition.md) and [`backend-module-registration.md`](backend-module-registration.md). Their local composition tests and runtime checks are recorded in each contract. Keep unverified behavior and known follow-up findings explicit; distinguish proposals from validated behavior.
