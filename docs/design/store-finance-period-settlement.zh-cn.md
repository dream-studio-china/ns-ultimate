# 门店财务与周期净结算流程

**状态：业务口径确认稿，尚未开始实现。**

本文用于固定门店财务、总部集中收款、总部送货记账和周期净结算的业务边界。后续实现不得把采购记成门店现金付款，也不得把总部代收货款直接当成门店银行卡余额。

## 1. 已确认的业务事实

1. 门店以个体户经营为主，不设置专门财务审核岗。
2. 顾客支付的资金由系统统一收取并归集到总部控制的收款渠道或账户。
3. 支付资金虽然由总部实际持有，但收入归属对应门店，并在门店财务中记账。
4. 总部负责向门店送货。门店确认收货时必须上传送货单等凭证，确认后立即形成门店对总部的采购应付款，门店不直接向供应商付款。
5. 每个门店设置自己的结算周期，可以按日结算，也可以按自定义月度周期结算。
6. 门店营收正式入账后，系统即可使用该门店由总部代收的资金划扣已确认采购欠款，不要求等到结算日。
7. 结算周期结束时生成结算单，处理尚未划扣的欠款、待转下期和剩余应付门店款，再把剩余净额结算给门店。
8. 薪资、铺租、水电、临时支出等由门店自行支付，不进入“总部代收资金减采购款”的净结算公式。
9. 所有收入、采购、费用和结算资金变动最终以会计凭证为财务事实来源。
10. 普通门店员工只能查看营收；门店负责人可查看本店完整财务摘要和明细，并完成确认入账、周期确认。
11. 凭证从 `draft` 过账为 `posted` 前必须具备可核查的原始凭证；人工录入业务必须上传附件，系统自动业务必须绑定不可变的源流水。

### 1.1 门店端最终使用效果

门店负责人进入系统后，应能直接看懂以下内容：

1. **每日采购金额**：当天确认收货的采购总金额、送货单照片、欠款余额和划扣状态。
2. **每日营收金额**：当天支付成功金额、成功退款和净营收，不区分支付渠道。
3. **每日固定支出分摊**：按费用覆盖日期计算每日工资、铺租等固定支出；水电等可变费用按实际账单记录，也可以单独设置预算后展示差异。
4. **每日保本线**：结合当日固定支出分摊和采购成本率，计算当天至少需要做到多少营收。
5. **每日经营结果**：实际营收、采购、固定支出、利润以及相对保本线的差额。
6. **周期营收利润单**：结算日自动汇总周期总营收、总退款、总采购、固定支出和经营利润。
7. **周期结算申领金额**：总部代收营收减去总部送货采购和待转下期后的应付门店金额。
8. **门店自付费用状态**：薪资、房租、水电和其他支出由门店线下支付，系统只记录凭证、支付状态和附件，不进入总部净结算计算。

## 2. 不采用的模型

以下模型均不符合本业务：

- 不把每笔顾客支付直接结入门店银行卡。
- 不把总部送货采购记成门店现金或银行卡付款。
- 不使用“门店钱包余额”代替总部代收资金和总部往来账。
- 不让总部送货收货记录停留在独立台账、不进入会计凭证。
- 不把薪资、房租等门店自付款从总部代收资金中扣除。
- 不按汇付或其他单一支付渠道设计独立财务逻辑。所有支付渠道先转换成统一的“收款成功、退款成功”事实。
- 不把会计凭证的 `draft -> posted` 改造成多级审批。门店负责人确认即执行 `post`，不增加 `pending_review`、`approved` 等会计凭证状态。

## 3. 核心术语

| 术语 | 含义 |
| --- | --- |
| 总部代收资金 | 顾客付款后由总部渠道实际持有、但归属门店的内部资金 |
| 门店营业收入 | 支付成功金额减去退款成功金额，按付款和退款归属门店 |
| 总部送货采购凭证 | 门店确认总部送货到店后生成的采购债务凭证 |
| 采购应付款 | 门店因已收货但尚未通过结算扣除而欠总部的款项 |
| 已确认收货 | 门店核对线下送货单并上传照片、录入总金额后确认，采购债务正式成立 |
| 可划扣资金 | 已过账且归属门店、尚未被退款、采购划扣或结算打款占用的总部代收资金 |
| 采购划扣 | 用门店可划扣资金核销总部采购应付款；必须生成独立划扣记录 |
| 门店自付费用 | 薪资、铺租、水电、临时支出等由门店自行支付的费用 |
| 结算周期 | 每个门店独立配置的起止日期范围 |
| 结算快照 | 确认结算时冻结的收入、退款、采购、调整和打款金额，不随之后的源数据变化 |
| 门店净额 | 总部代收资金减去已确认采购款及其他经批准调整后的可结算金额 |
| 待转下期 | 已发生但尚未在本次结算中打款或扣除的金额，包括负余额 |

## 4. 资金关系

```text
顾客
  -> 支付渠道
  -> 总部控制账户
  -> 归属于具体门店的收入
  -> 形成总部对门店的资金持有

总部送货
  -> 门店收货
  -> 上传送货单并确认收货
  -> 形成门店对总部的采购应付款

门店营收入账
  -> 形成可划扣资金
  -> 按最早未结采购应付款划扣
  -> 采购欠款变为部分结清或已结清

结算日
  -> 尚未结算的总部代收资金
  - 仍未划扣的采购应付款
  - 其他经门店确认的总部调整
  = 本次应打款净额
```

总部实际持有的资金不能直接解释为总部收入。它同时包含：

- 总部应结算给门店的净额。
- 总部因送货形成的采购回款。
- 后续可能定义的渠道费、调整项；第一版未确认前不得自动扣除。

## 5. 端到端流程

### 5.1 顾客支付与收入记账

1. 顾客完成支付，支付渠道返回可信的支付成功事实。
2. 系统根据订单确定门店，不根据支付渠道的商户名称猜测门店。
3. 支付成功事实记录归属门店、订单、金额、币种、支付时间和渠道流水号。
4. 系统按门店、日期汇总生成营业收入凭证。凭证可以使用日汇总，不需要每一笔支付单独生成一张凭证。
5. 凭证过账后进入门店营收和财务摘要。

统一财务口径：

```text
营业额 = 周期内支付成功金额
营业收入 = 营业额 - 周期内退款成功金额
```

处理中、失败、已取消的退款不计入退款金额。跨周期退款进入退款实际成功的周期，并形成下一周期调整或待转下期余额；不得修改已经关闭的历史结算单。

### 5.2 总部送货与采购记账

总部送货通过线下沟通，送货明细以总部实际送货单为准，系统第一版不要求总部提前创建送货单或录入商品级明细。

门店确认收货时执行一个简单表单：

1. 选择收货日期，默认当天。
2. 输入本次送货总金额。
3. 拍照或上传总部送货单，送货单照片为必填项。
4. 可选填写送货单号、备注。
5. 点击“确认收货”。

门店确认收货后，后端直接完成以下动作：

1. 生成一张采购凭证，业务类型为 `hq_delivery_purchase`。
2. 将送货单照片写入 `attachments`。
3. 将收货日期、总金额、可选送货单号和来源写入 `metadata`。
4. 在同一业务动作中完成凭证过账，形成门店采购成本和对总部采购应付款。

第一版采购凭证不要求商品、数量、单价等逐项明细。送货单照片作为业务明细核查依据，系统只记录本次送货总金额。没有送货单照片、没有有效总金额或门店不匹配时，不能确认收货。

采购凭证创建后归属固定门店，不接受前端传入其他门店 UUID。金额或照片有误时，通过反冲原凭证并重新确认一张采购凭证更正，不直接覆盖已经过账的历史。

采购业务同时维护店铺可读状态：

```text
待收货
  -> 已确认收货，欠款未结清
  -> 部分划扣
  -> 已划扣结清
```

这些是采购业务状态，不改变会计凭证的 `draft -> posted` 状态。采购凭证在确认收货时已经正式过账；之后的“划扣结清”是另一笔核销事实，不能通过修改原采购凭证金额表示。

### 5.2.1 营收划扣采购欠款

门店营收凭证过账后形成可划扣资金。系统可以按以下规则核销采购欠款：

1. 只使用已经过账、归属本门店且尚未被其他业务占用的营收资金。
2. 只核销门店已经确认收货且附有送货凭证的采购应付款。
3. 默认按采购确认时间从早到晚核销；有需要时也可以指定具体采购凭证定向核销。
4. 允许部分划扣。可划扣资金小于欠款时，欠款剩余金额继续保留。
5. 同一笔营收不能重复用于采购划扣、退款或门店结算打款。
6. 每次划扣生成独立的 `hq_procurement_offset` 划扣记录和会计凭证，引用对应营收、采购凭证及送货单附件。
7. 划扣凭证正式过账后，采购单显示“部分划扣”或“已划扣结清”，并展示划扣时间、金额、操作来源及剩余欠款。
8. 自动划扣和人工划扣使用同一后端规则和幂等键，重复请求不能重复扣款。

可划扣资金按以下方式计算：

```text
可划扣资金
= 已过账门店营收
- 已成功退款
- 已过账采购划扣
- 已结算打款
- 已冻结或预留金额
```

结果小于零时按零处理，不得产生负的可划扣资金。未来周期尚未到账的营收不能提前用于当前划扣。

划扣对应的会计处理为：借记“总部采购应付款”，贷记“总部代收资金往来”。原采购凭证和原营收凭证保持不可变，划扣以独立凭证作为核销依据。

如果门店采用日结，可以在每日营收过账后立即执行划扣；如果采用自定义月度周期，也可以在周期内每日或按配置时点执行划扣。未划扣完的采购欠款自动进入下一次可用资金或结算日继续处理。

### 5.3 门店自付费用

薪资、铺租、水电煤气、维修及其他临时支出由门店自行支付：

1. 门店负责人在门店端录入费用。
2. 可上传发票、付款截图或收据。
3. 保存时生成会计凭证草稿。
4. 门店负责人核对后直接过账。
5. 该费用进入门店利润表，但不改变总部代收资金，也不从周期结算金额中扣除。

如门店尚未支付但需要按权责发生制记账，可单独标记“应付未付”，不得把该金额误认为总部已经代付。

### 5.3.1 每日经营视图

每日经营视图按门店时区展示以下数据：

| 指标 | 计算方式 |
| --- | --- |
| 当日营业额 | 当日支付成功金额 |
| 当日退款 | 当日退款成功金额 |
| 当日营业收入 | 当日营业额 - 当日退款 |
| 当日采购发生额 | 当日总部送货金额，同时显示待确认和已确认状态 |
| 当日已确认采购额 | 当日送货中已经由门店确认并过账的采购金额 |
| 当日预估毛利 | 当日营业收入 - 当日采购发生额 |
| 当日正式毛利 | 当日营业收入 - 当日已确认采购额 |
| 当日固定支出分摊 | 汇总当日生效的固定支出日分摊金额 |
| 当日预估经营利润 | 当日预估毛利 - 当日固定支出分摊 - 当日其他门店自付费用 |
| 当日正式经营利润 | 当日正式毛利 - 当日固定支出分摊 - 当日其他门店自付费用 |
| 当日保本营收 | 当日固定支出分摊 / (1 - 采购成本率) |
| 距离保本差额 | 当日营业收入 - 当日保本营收 |

采购成本率优先使用当前结算周期累计值：

```text
采购成本率 = 本周期累计采购金额 / 本周期累计营业收入
```

周期刚开始、数据不足或营业收入为零时，可以同时展示参考成本率，并明确标记保本线为“估算”。参考成本率使用最近一个完整结算周期；没有完整周期数据时显示“暂无法计算”，不能用固定猜测值冒充实际结果。

固定支出分摊只是经营分析计算，不要求每天生成一张凭证：

1. 每个固定支出仍按实际业务生成一张月度或周期费用凭证。
2. 每个固定支出记录费用金额、生效开始日和生效结束日，系统按覆盖自然日平均分摊到每日。
3. 多个固定费用相加得到每日固定支出总额。
4. 分摊金额只进入日报、利润单和保本线，不额外产生每日会计凭证。
5. 固定支出尚未支付时，经营分析仍可按已确认的费用记录计算，同时显示“线下未支付”；支付状态与会计费用确认分开记录。

固定支出必须拆成“固定支出设置项”和“每期费用凭证”两层：

| 层级 | 用途 | 是否每月更新 |
| --- | --- | --- |
| 固定支出设置项 | 定义费用类别、默认金额、覆盖周期、付款对象、是否需要门店确认等重复规则 | 规则变化时才更新 |
| 每期固定支出凭证 | 记录该门店在该费用周期实际发生的费用、附件、确认人、入账状态和线下支付状态 | 每个费用周期生成一张 |

示例：

```text
设置项：铺租，每月 10,000 元，覆盖自然月
  2026-01 凭证：10,000 元，附 1 月房租凭证
  2026-02 凭证：10,500 元，附 2 月房租凭证及调价说明
```

具体规则：

1. 设置项本身不是会计凭证，不直接进入损益和结算。
2. 每个设置项在每个费用周期自动生成一张费用凭证草稿，并记录“来源设置项 UUID + 费用周期”。
3. 同门店、同设置项、同费用周期只能生成一张有效凭证，重复生成必须返回原凭证。
4. 固定金额可以直接带入草稿；金额可能变化的费用由门店负责人确认实际金额。
5. 门店负责人核对金额、上传本期凭证并确认过账。
6. 已过账凭证不能因设置项以后改价而变化，历史金额保持不可变。
7. 线下支付状态单独记录为“未支付、部分支付、已支付”，不通过修改已过账凭证表示。
8. 每日固定支出分摊从每期已确认凭证金额和实际覆盖日期派生，不保存为每日会计凭证。

因此，一个铺租设置项会产生多期铺租凭证；一个工资设置项可以对应每月一张工资凭证。若门店同时有多个独立固定费用，应分别建立设置项，方便每期核对和支付状态跟踪。

例如月度铺租覆盖 1 月 1 日至 1 月 31 日，则每天分摊金额为租金除以 31。门店结算周期为 1 月 26 日至 2 月 25 日时，周期固定支出由 1 月 26 日至 31 日、2 月 1 日至 25 日两段分摊金额加总，不能简单按自然月重复计算。

日报在周期结算前属于“经营预估”，使用已发生的总部送货金额计算预估利润；门店确认采购后转化为正式利润。页面必须清楚显示采购状态，不得把待确认采购当成已确定扣款，也不得因为尚未到结算日就隐藏当天已经发生的送货金额。

### 5.4 周期结算预览

每个门店配置自己的结算方式。支持每日结算，也支持自定义月度周期，例如每月 26 日：

```text
2026-01-26 00:00:00 至 2026-02-25 23:59:59.999999
```

日期归属必须按门店时区计算。起始日在短月超过月末时，按当月最后一天处理。

日结门店每天生成一张结算单；自定义周期门店在周期结束日生成。两者使用相同的采购欠款、营收资金、划扣、利润和申领规则。

周期结束时，系统生成结算预览：

```text
期初待转下期余额
+ 本周期支付成功金额
- 本周期退款成功金额
- 本周期门店已确认的总部送货采购款（包括周期内已经划扣和尚未划扣的部分）
+/- 本周期经门店确认的总部调整
= 本周期可结算余额
```

采购划扣只是把“已确认采购欠款”和“门店可划扣营收资金”做核销，不改变本周期采购总额。计算结算申领时不能再把已经划扣的采购重复减一次；划扣前后的应付净额由统一门店资金余额计算，并可通过采购欠款明细、划扣记录和结算单逐项勾稽。

如果可结算余额大于零，则本次打款金额等于可结算余额；如果小于零，则本次不向门店打款，负数作为“门店欠总部”的待转下期余额。

第一版默认没有渠道费、税、品牌费或其他总部自动扣款。新增任何扣款类型都必须进入结算明细并向门店展示原因，不得在后台无明细直接扣减。

### 5.4.1 营收利润单与结算申领单

系统在结算日自动生成两张相互关联但不能混用的单据：

1. **营收利润单**：用于门店经营分析。
2. **结算申领单**：用于门店向总部申请周期结算款。

营收利润单口径：

```text
营业收入
- 总部送货采购
- 固定支出
- 其他门店自付费用
= 经营利润
```

结算申领单口径：

```text
营业收入
- 已确认总部送货采购
+/- 待转下期和经确认的总部调整
= 向总部申领金额
```

薪资、铺租、水电和其他门店自付费用会降低经营利润，但**不得从总部应付款中再次扣除**。门店收到总部结算款后，在线下自行支付这些费用。

如果经营利润与申领金额不同，页面必须分别解释原因，不能让门店误以为利润就是总部应打款金额。

### 5.5 门店确认

1. 门店负责人查看结算单，包括收入、退款、采购凭证总金额、送货单照片、采购欠款和划扣状态、待转下期及预计打款金额。
2. 门店只可操作当前会话授权的门店，不接受客户端传入其他门店 UUID 进行确认。
3. 门店确认后，结算单冻结为本周期快照。
4. 纳入本次结算的总部送货必须在门店确认收货时已经上传凭证并正式过账；未确认收货、未过账或存在争议的采购不得参与本次申领和打款。
5. 已确认结算单不得直接修改。发现错误必须通过反冲、补记和下一周期调整处理。
6. 门店确认营收利润单和采购记录后，点击“向总部申领结算”提交结算申领单。
7. 申领提交后进入总部打款环节；提交动作记录门店负责人、时间、金额和确认版本。

会计凭证仍使用现有状态：

```text
draft --门店负责人确认--> posted
draft --作废----------> voided
posted --错误更正------> 独立反冲凭证
```

这里不新增会计凭证审核状态。结算单自身的业务状态用于控制打款过程，与总账凭证状态不是同一概念。

### 5.6 过账附件要求

`draft -> posted` 时必须有足以核查该笔业务的原始凭证。附件不是仅供展示的可选项，而是过账校验条件。

总部送货采购凭证在门店“确认收货”时创建并过账，不是在结算日才过账。门店确认收货时必须同时提交送货单照片和本次总金额。

人工录入或总部送货产生的凭证，过账前至少需要一个有效附件：

| 业务类型 | 最低凭证要求 |
| --- | --- |
| 总部送货采购 | 门店签收的总部送货单照片，必填一项或多项 |
| 门店薪资 | 工资表、支付截图或银行流水，至少一项 |
| 门店铺租 | 合同、房东收据、发票或银行流水，至少一项 |
| 水电及其他费用 | 账单、发票、收据或支付凭证，至少一项 |
| 人工调整 | 调整说明、审批记录和对应证明，至少一项 |

规则如下：

1. 草稿可以先保存并显示“缺少凭证”，方便后续补传。
2. 门店负责人确认过账前，必须能够查看附件内容。
3. 后端过账接口必须检查本店范围内的有效附件；没有附件返回明确的业务错误，不能只在前端禁用按钮。
4. 附件必须关联当前凭证，不能只把图片上传到临时位置。
5. 已过账凭证的附件不得删除或替换。需要补充资料时追加说明或补充附件，并记录操作人和时间。
6. 已过账凭证更正时，反冲凭证必须引用原凭证及原附件；必要时附加更正说明。

系统自动生成的收入、退款和实际打款凭证不以人工图片作为唯一依据，但必须绑定不可变、可追溯的系统凭证：

| 业务类型 | 系统凭证 |
| --- | --- |
| 顾客支付收入 | 订单 UUID、支付成功流水、支付时间、金额和渠道 |
| 顾客退款 | 原支付流水、退款成功流水、退款时间和金额 |
| 采购划扣 | 原采购凭证、原送货单附件、营收凭证、划扣时间和金额 |
| 实际打款 | 结算单 UUID、打款批次、银行或支付渠道成功回执 |
| 自动反冲 | 原凭证 UUID、原系统流水和反冲原因 |

收入、退款或打款没有可信源流水时不得过账。实际打款凭证应在渠道确认成功并取得回执后再过账；打款请求中或失败时不能生成“已打款”的正式凭证。

当前会计后端已经支持 `attachments`，但现有 `post` 流程并未强制人工凭证必须带附件。实现本流程时需要增加后端过账校验，并补充无送货单确认收货、跨店附件、失效附件和重复过账的测试。

### 5.7 总部划扣与结算打款

```text
结算预览
  -> 门店确认
  -> 汇总本周期已划扣和未划扣采购
  -> 总部财务执行
  -> 打款处理中
  -> 打款成功，结算关闭
  -> 打款失败，可重试，不重复扣款
```

执行结算时必须保存：

- 结算单 UUID。
- 门店 UUID 和会计账簿。
- 周期实际起止时间。
- 收入、退款和采购金额快照。
- 已划扣和未划扣的送货单、采购凭证、划扣凭证 UUID 列表。
- 门店确认人和确认时间。
- 总部执行人和执行时间。
- 银行或支付渠道打款流水号。
- 打款失败原因和重试次数。

门店确认只表示认可本周期结算内容。总部执行打款前仍可发现银行账户信息错误，但不得修改已确认金额；只能取消本次打款、保留确认快照并重新发起同一结算单的打款。

采购划扣和结算打款是两个独立动作：

- 采购划扣可以在周期内发生，只改变门店欠总部采购款和可划扣资金。
- 结算打款只在门店提交结算申领后发生，代表总部把剩余归属门店资金支付给门店。
- 日结门店可以每天先划扣当日可用采购欠款，再对剩余金额生成当日结算申领。

### 5.8 打款后退款

结算关闭后如果原订单又发生成功退款：

1. 不修改历史结算金额。
2. 在退款成功所属周期创建独立退款调整。
3. 优先从下一周期门店净额中扣除。
4. 如果下一周期仍不足，继续形成门店欠总部的待转下期余额。
5. 所有调整保留原订单、退款、原支付和原结算单引用。

不要通过删除或覆盖原收入凭证来隐藏退款。

## 6. 采购、划扣与结算业务状态

采购单使用以下业务状态：

```text
confirmed_receivable
  -> partially_offset
  -> settled
```

采购单在 `confirmed_receivable` 时已经生成并过账采购凭证。`partially_offset`、`settled` 表示欠款核销进度，不修改原采购凭证。

采购划扣记录使用以下状态：

```text
draft
  -> posted
  -> reversed
```

划扣凭证在 `posted` 后正式反映欠款减少和门店资金减少。失败或未过账的划扣不能改变采购欠款余额。

结算单使用以下业务状态，不改变会计凭证状态：

```text
calculating
  -> pending_store_confirmation
  -> claimed
  -> payout_processing
  -> paid
  -> closed

payout_processing
  -> payout_failed
  -> payout_processing (retry)
```

规则：

- `calculating`：正在读取订单、退款和采购凭证，生成预览。
- `pending_store_confirmation`：预览已冻结，等待门店负责人确认。
- `claimed`：门店已确认营收利润单并提交结算申领，金额不可直接修改。
- `payout_processing`：总部已发起打款，禁止重复执行。
- `payout_failed`：打款失败，可使用同一结算快照重试。
- `paid`：渠道确认成功，记录打款流水。
- `closed`：结算及对应会计凭证关联完成。

同一门店、同一周期只能有一个可执行结算单。生成操作使用稳定幂等键，重复点击返回原结算单。

## 7. 门店账簿与会计科目建议

门店负责人无需选择会计科目。后端根据业务类型自动生成借贷行。

### 7.1 门店账

| 业务 | 借方 | 贷方 | 是否影响总部净结算 |
| --- | --- | --- | --- |
| 顾客支付收入 | 总部代收资金往来 | 营业收入 | 是，增加可结算金额 |
| 成功退款 | 销售退款 | 总部代收资金往来 | 是，减少可结算金额 |
| 总部送货采购确认收货 | 食材/商品成本 | 总部采购应付款 | 是，形成门店采购欠款 |
| 采购欠款划扣 | 总部采购应付款 | 总部代收资金往来 | 是，核销欠款并减少可划扣资金 |
| 门店自付薪资 | 薪资费用 | 门店银行/现金 | 否 |
| 门店自付铺租 | 租金费用 | 门店银行/现金 | 否 |
| 门店自付水电及其他费用 | 对应经营费用 | 门店银行/现金 | 否 |
| 总部净额打款 | 门店银行 | 总部代收资金往来 | 是，减少总部持有的门店资金 |
| 打款后退款调整 | 销售退款/待转下期 | 总部代收资金往来 | 是，减少后续可结算金额 |

“总部代收资金往来”是受控内部往来科目。单个门店账中可显示净余额，但报表需要分别提供总部代收、采购扣减和实际打款的明细，不能仅展示一个无法解释的余额。

### 7.2 总部汇总

总部汇总层至少区分：

- 渠道实际收到的资金。
- 已归属门店但尚未结算的资金。
- 已确认采购形成的总部应收回款。
- 已打款给门店的资金。
- 当前仍由总部持有的门店净资金。

`Wallet` 中的余额记录或 `Settlement` 的分配成功记录都不能单独证明银行已经打款。实际打款必须有独立渠道回执。

## 8. 凭证业务类型

后端接受业务类型，不接受门店直接提交会计科目和借贷方向：

```text
customer_revenue
customer_refund
hq_delivery_purchase
hq_procurement_offset
store_salary
store_rent
store_utility
store_other_expense
settlement_payout
post_settlement_refund_adjustment
```

每个业务类型由后端维护科目映射。凭证 `metadata` 建议包含：

```json
{
  "business_type": "hq_delivery_purchase",
  "store_uuid": "<store-uuid>",
  "source_type": "hq_delivery",
  "source_uuid": "<delivery-uuid>",
  "source_number": "DEL-2026-0001",
  "settlement_period": "2026-01-26_2026-02-25",
  "self_paid": false,
  "offset_status": "partially_offset"
}
```

第一版总部送货只记录总金额，不保存商品级采购明细。送货单照片是采购明细的核查依据；`metadata` 仅保存收货日期、可选送货单号、来源和划扣状态等有限信息。

电子凭证继续使用现有 `attachments` 字段。门店端读取附件时必须同时检查门店、结算单和凭证归属，不能复用总部无范围限制的附件读取权限。

## 9. 权限边界

### 9.1 普通门店员工

```text
store:revenue:read
```

只能查看本店营收汇总和营收明细，不显示会计科目、采购成本、费用利润和总部往来。

### 9.2 门店负责人

```text
store:accounting:read
store:accounting:draft
store:accounting:post
store:accounting:attachment:read
store:purchase:receive
store:settlement:read
store:settlement:confirm
```

只能操作当前门店。门店负责人可以录入门店自付费用、填写采购总金额、上传送货单照片、确认收货、查看采购划扣、确认结算单和将本店草稿凭证过账。

### 9.3 总部

```text
hq:purchase:read
hq:procurement:offset
hq:settlement:read
hq:settlement:execute
hq:settlement:adjust
```

总部负责线下送货、查看门店已确认采购、结算预览、扣除明细解释和实际打款。总部不能绕过门店确认把未确认采购直接计入净扣款。

系统管理员拥有全部权限，但仍必须按门店范围读取数据，并保留完整审计记录。

## 10. 数据与幂等约束

所有金额使用整数最小货币单位或精确十进制字符串，禁止使用浮点数。

必须具有稳定幂等键的事实：

- 支付成功：支付渠道 + 渠道流水号。
- 退款成功：支付渠道 + 退款流水号。
- 收货确认：门店 UUID + 客户端命令 UUID + 送货单照片内容哈希；可选送货单号不能作为唯一依据。
- 采购划扣：采购凭证 UUID + 营收凭证 UUID + 划扣金额 + 门店命令 UUID。
- 门店费用：门店 + 客户端命令 UUID。
- 结算单：门店 + 实际周期开始日期 + 实际周期结束日期。
- 打款：结算单 UUID + 打款尝试编号。
- 会计过账：凭证 UUID + revision + command UUID。

必须防止：

- 支付回调重复导致营收重复。
- 退款回调重复导致退款重复。
- 同一收货表单重复提交生成多张采购凭证。
- 同一采购欠款重复划扣或划扣超过剩余欠款。
- 同一营收资金同时用于采购划扣和结算打款。
- 重复点击结算生成多个可执行结算单。
- 打款超时后重复打款。
- 门店确认后总部再次修改采购金额。
- 跨店读取或确认结算单。
- 把处理中退款计为成功退款。

## 11. 与现有系统能力的衔接

| 现有能力 | 使用方式 |
| --- | --- |
| `JournalEntry`、`LedgerCommands` | 作为收入、采购、费用、退款和打款的正式财务记录 |
| `metadata` | 保存业务类型、来源、单据号和结算周期等有限业务快照 |
| `attachments` | 保存采购单、发票、收据和付款凭证 |
| `AccountingBook` | 每个门店独立账簿；总部做跨店汇总 |
| `AccountingPeriod` | 当前只支持自然月，实施自定义周期时必须扩展为实际起止日期 |
| `StoreCashEntry` | 不能作为总部送货的正式会计记录；可保留为门店自付现金流水或后续合并到凭证入口 |
| Core `Settlement` | 只适合分配已确认 funding，不负责门店应收应付净额、采购抵扣或银行打款；不得把 Wallet credit 当作银行到账证明 |
| Core `Wallet` | 可作为内部资金账户能力；本项目不应仅依赖钱包余额证明总部净打款 |

业务代码优先放在 `business/backend/Accounting` 或新的门店财务业务模块。除非明确批准，不修改 `core/`。

## 12. 第一版范围

第一版必须完成：

- 门店独立结算周期。
- 每日营收、每日采购、每日固定支出分摊、每日经营利润和每日保本线。
- 统一支付成功和退款成功事实，不区分支付渠道。
- 每日或周期收入凭证。
- 门店确认收货时拍照上传总部送货单、输入总金额，并正式生成采购凭证和采购欠款。
- 营收入账后按最早欠款执行部分或全部划扣，划扣凭证正式过账并显示核销状态。
- 门店自付费用凭证。
- 周期结算预览。
- 自动生成关联的营收利润单和结算申领单。
- 门店负责人确认并过账相关凭证。
- 人工业务凭证缺少附件时禁止过账，收入、退款和打款必须绑定系统源流水。
- 采购款净额扣除。
- 净额打款记录、失败重试和打款回执。
- 普通员工只看营收的权限。
- 采购成本毛利和扣除自付费用后的纯利摘要。

第一版不包含：

- 税费自动计算和法定税务申报。
- 支付渠道手续费自动扣除，除非后续明确费率和入账方式。
- 银行自动转账的完整供应商适配；可先支持人工打款回执录入。
- 总部与门店之间的复杂多级审批。
- 负余额自动向门店银行扣款。

## 13. 验收场景

1. 门店周期为 26 日至次月 25 日，付款在周期边界前后能归入正确结算单。
2. 同一支付回调重复 10 次，只产生一次收入。
3. 退款处理中不计入扣减，退款成功后只扣减一次。
4. 门店新增采购时只输入收货日期和总金额并上传送货单照片，系统生成正式采购凭证；没有总金额或送货单照片时不能确认收货。
5. 门店未确认收货或未上传送货单时，采购不能正式建立欠款，也不能划扣。
6. 门店确认收货并上传送货单后，采购凭证变为 `posted`，门店出现准确采购欠款。
7. 门店 A 的负责人不能查看或确认门店 B 的送货和结算。
8. 门店自付的薪资、铺租和水电能够进入利润，但完全不改变总部净结算金额。
9. 可结算余额为负时，本次打款为零，负余额完整转入下期。
10. 打款接口超时后重试，只产生一笔有效打款。
11. 打款成功后发生退款，历史结算单不变，下一期出现退款调整。
12. 普通员工只能读取本店营收，无法读取采购、成本、会计科目和附件。
13. 门店负责人获得的本店收入、退款、采购和打款汇总，与对应已过账凭证逐项可追溯。
14. 所有渠道的支付都通过同一财务口径汇总，不存在汇付或某个渠道的独立结算流程。
15. 有附件的人工凭证可以过账；无附件的人工凭证无论从前端还是直接调用接口都返回过账失败。
16. 门店负责人只能查看和引用本店凭证附件，不能通过附件 URL 读取其他门店资料。
17. 收入、退款和打款缺少可信源流水时不能过账，处理中或失败的退款、打款不能显示为已完成。
18. 每日采购金额、每日营业收入、固定支出分摊、经营利润和保本线可以在门店端按日期查看。
19. 固定支出分摊不生成每日凭证，只从月度或周期费用凭证派生。
20. 门店确认周期数据后可以提交结算申领；申领金额等于营业收入减已确认总部采购及周期调整，不再扣减薪资、铺租等门店自付费用。
21. 同一周期的营收利润单与结算申领单金额能够逐项勾稽，经营利润和申领金额的差异有明确说明。
22. 有已过账营收时，可以按最早采购欠款划扣；资金不足时只允许部分划扣，剩余欠款准确保留。
23. 划扣成功后生成正式过账记录，采购单显示部分划扣或已结清，原采购凭证金额不变。
24. 日结门店每天可以完成收货确认、营收过账、采购划扣、结算申领和打款，新一天不会重复使用前一天资金。
